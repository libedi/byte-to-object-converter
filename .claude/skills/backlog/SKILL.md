# 백로그 관리

이 프로젝트의 백로그 파일을 일관된 형식(미완료/완료 두 섹션, `#BL-NN`/`#BC-NN` 안정 ID, 완료 시 요약 압축)으로 읽고 쓴다. `.claude/rules/backlog.md`가 다른 스킬/에이전트에게 이 스킬을 참고하라고 알려주는 짧은 포인터다 — 실제 형식 규칙의 원본은 이 파일 하나뿐이다.

## 백로그 파일 찾기/만들기

1. 프로젝트에 백로그 파일이 있는지 확인한다. 기본 경로는 `docs/backlog.md`다. 이미 다른 경로에 있다는 걸 알고 있으면(과거 대화나 `.claude/rules/backlog.md`에 기록됨) 그 경로가 실제로 존재하는지부터 다시 확인한다.
2. 없으면 사용자에게 저장 위치를 묻는다 — 기본값으로 `docs/backlog.md`를 제안한다. **파일명은 항상 `backlog.md`로 고정**하고, 디렉토리만 사용자가 원하는 대로 정한다.
3. 새로 만들 때: 아래 "파일 구조"의 빈 템플릿으로 파일을 생성하고, 저장소 루트 `.gitignore`에 `backlog.md` 패턴이 이미 있는지 확인한다 — 없으면 파일 끝에 추가하고(있으면 손대지 않는다), 이미 git에 커밋되어 추적 중인 동일 경로 파일이 있다면 `git rm --cached`로 언트랙할지 사용자에게 물어본다(gitignore 패턴은 새로 추가되는 파일에만 적용되고 이미 추적 중인 파일에는 적용되지 않는 git의 특성 때문).

## 파일 구조

```markdown
# 백로그

## 미완료

- #BL-01. 항목 제목
  - 진행 메모, 하위 체크리스트, 막힌 지점 등 자유 형식 — 완료 전까지는 분량 제한 없음
- #BL-02. 다른 항목

---

## 완료

- #BC-01. 항목 제목 (완료일, 관련 커밋 해시가 있으면 함께, 구 #BL-02)
  결과를 한 줄로 요약
```

- 두 섹션은 `## 미완료`, `## 완료` 두 개의 H2 헤딩이고 그 사이를 `---`(수평선)로 구분한다.
- 이 스킬은 항목을 주제(토픽)별로 다시 묶지 않는다 — 미완료/완료 각각 하나의 평평한 목록이다. 어떤 주제인지는 항목 제목 자체에 드러나게 쓴다(예: "V2 로드맵 Phase 5 — 문서화").
- 완료 여부는 섹션 자체가 나타내므로 `- [ ]`/`- [x]` 체크박스는 쓰지 않는다 — 그냥 `-` 목록이다(항목 안의 하위 진행 체크리스트에는 체크박스를 써도 된다).

## ID 규칙

- 미완료 항목은 `#BL-NN`, 완료 항목은 `#BC-NN`을 쓴다. 두 접두사는 완전히 별개의 채번 풀이다. `#`은 ID의 일부이고, 뒤따르는 `.`은 제목과 구분하는 구분자다(예: `#BL-01. 제목`).
- **번호는 절대 재사용하지 않고, 재정렬하지 않는다.** 다른 문서가 `#BL-05`처럼 특정 ID를 참조하고 있을 수 있으므로, 항목이 사라지거나 이동해도 그 번호를 다른 항목에 다시 붙이지 않는다.
- 새 미완료 항목의 NN은 **지금까지 한 번이라도 쓰인 `#BL-NN` 중 가장 큰 번호 + 1**이다. 현재 `## 미완료`에 남아있는 `#BL-NN`뿐 아니라, `## 완료`에 남아있는 `(구 #BL-NN)` 표기까지 함께 훑어서 계산한다 — 완료되어 미완료 목록에서 사라진 번호도 "이미 쓰인 번호"이기 때문이다.
- 새 완료 항목의 NN은 **`## 완료`에 이미 있는 `#BC-NN` 중 가장 큰 번호 + 1**이다.
- 두 자리(01, 02, ...)로 0-패딩한다.

## 항목 추가

1. 다음 `#BL-NN`을 위 ID 규칙대로 계산해 부여하고, `## 미완료`에 목록 항목(`- #BL-NN. 제목`)으로 추가한다.
2. 진행 중 세부 내용(하위 체크리스트, 결정 사항, 막힌 지점)은 그 항목 아래에 자유롭게 적는다.

## 항목 완료 처리

1. **완료되는 항목은 새 ID를 받는다 — 기존 `#BL-NN`을 그대로 옮기지 않는다.** 다음 `#BC-NN`을 ID 규칙대로 계산한다.
2. `## 미완료`에서 그 항목(하위 상세 내용 포함)을 전부 지운다.
3. `## 완료`에 그 `#BC-NN`으로 새로 추가하되, **딱 두 줄만 남긴다**: 첫 줄은 `- #BC-NN. 제목 (완료일[, 관련 커밋 해시][, 구 #BL-NN])`, 둘째 줄은 들여쓴 한 줄짜리 결과 요약. 원래 미완료였던 항목이면 `구 #BL-NN`을 반드시 남긴다(추적성 + 다음 `BL` 번호 계산의 근거가 된다). 새 항목이 미완료를 거치지 않고 바로 완료로 기록되는 경우(예: 과거에 이미 끝난 작업을 소급 기록)라면 `구 #BL-NN`은 생략한다.
4. `## 완료`에는 완료 시점 순으로 맨 아래에 추가한다(재정렬하지 않는다) — 순서 자체가 곧 완료 이력이 된다.
5. 완료 처리 전에 요약 문구를 사용자에게 보여주고 확인받는다 — 무엇을 요약에서 뺄지는 되돌릴 수 없는 손실이므로 임의로 판단하지 않는다.

## Gotchas

- 완료된 항목은 요약 두 줄만 남기고 상세를 지우는 게 원칙이다 — 상세 근거가 필요해지면 요약에 남긴 커밋 해시로 `git log`를 보게 한다. 이 요약 자체를 나중에 다시 늘리지 않는다.
- `(구 #BL-NN)`을 빠뜨리면 다음 `BL` 번호 계산이 틀어질 수 있다 — 완료 처리 시 절대 생략하지 않는다(소급 기록 예외 제외).
- 아직 커밋되지 않은 작업을 완료 처리할 때는 존재하지 않는 커밋 해시를 지어내지 않는다 — "미커밋"이라고 그대로 적는다.
